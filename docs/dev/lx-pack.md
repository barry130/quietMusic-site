# 洛雪（LX）音源脚本打包与使用

你手上已经有一份 **LX Music 自定义源脚本**（一个 `.js`，比如「某某音源 v3.js」），
想在轻听里用它播歌。本页讲的就是：**怎么把它变成一个可安装的播放包，以及装进去之后怎么用。**

::: tip 三步走完
① 一条命令打包 → ② 客户端「从本地文件」安装 → ③ 播首歌验证。

命令：

```bash
node scripts/build-lx-pack.mjs "我的洛雪源.js" --id my-lx-source
```
:::

- 只想照着做：跳到 [2. 打包](#_2-打包) 和 [3. 安装](#_3-安装)。
- 想知道它凭什么能跑、哪些源会跑不通：[5. 支持范围与已知边界](#_5-支持范围与已知边界)。
- 装完不出声：[6. 报错对照表](#_6-报错对照表)。

## 1. 先说清楚它是什么

轻听的播放包**只负责一件事**：把一首歌解析成一个可播放的地址（取链）。
洛雪源脚本干的也正是这件事——所以它们对得上，中间只需要一层转换。

打包器做的事，是把「一份洛雪源脚本」包成一个**标准的轻听播放包**：

```
你的洛雪源.js  ──打包器──▶  my-lx-source.js（播放包）
                              │
                              ├─ 首行包头：/*__QT_PACK__{"kind":"play",…}*/   宿主不执行就能读出身份
                              ├─ 内嵌的洛雪运行时桥（模拟 lx 对象、加解密工具）
                              └─ 你的脚本原文（逐字节保全，一个字符都不改）
```

内嵌的那层「洛雪运行时桥」负责：模拟 `lx.on` / `lx.send` / `lx.request`、
实现 `utils.crypto`（md5 / AES）与 `utils.buffer`（utf8 / hex / base64），
并接住脚本里常见的 `process` / `window` 探测与定时器反调试。
**Android 与 Windows 两端共用同一份产物。**

### 它不做的事

| 不做 | 归谁 |
|---|---|
| 搜索、歌单、榜单、热词 | **数据包**（`meta-official`），与本工具无关 |
| 歌词、封面 | 同上 |
| 下载加速、MV | 轻听当前不提供 |

所以**洛雪包和官方数据包是叠加关系，不是替代关系**：洛雪包只接管「点开这首歌去哪取链」，
你在哪儿搜到这首歌、歌词封面从哪来，仍然是数据包的事。只装洛雪包不装数据包 = 能播但没内容可浏览。

## 2. 打包

### 2.1 环境

只需要 **Node.js ≥ 20**（用来跑打包脚本，跟客户端本身无关）。

拿到打包器 —— 在 [qt-sources-sdk](https://cnb.cool/canace/qt-sources-sdk) 仓库里：

```bash
git clone https://cnb.cool/canace/qt-sources-sdk.git
cd qt-sources-sdk
```

打包器是这个仓库里的 `scripts/build-lx-pack.mjs`，纯 Node 实现、**没有任何依赖**（不用 `npm install`）。

### 2.2 一条命令

```bash
node scripts/build-lx-pack.mjs "我的洛雪源.js" --id my-lx-source
```

产物就是当前目录下的 `my-lx-source.js`。

也可以走仓库里配好的脚本名（效果完全一样）：

```bash
pnpm build:lx -- "我的洛雪源.js" --id my-lx-source
```

### 2.3 输出长什么样

```text
已生成播放包：./my-lx-source.js
  大小      62.7 KB（源脚本 26.0 KB）
  包头      /*__QT_PACK__{"kind":"play","id":"lx-nianxin","name":"念心音源","versionCode":1,"versionName":"1.0.2"}*/
  预检      通过（无命中）
```

三行都要扫一眼：

- **包头**里的 `name` 是从脚本头部的 `@name` 读出来的，乱码或截断说明脚本头写得不规范
  （不影响运行，只影响列表里显示成什么样）；
- **预检**是最关键的一行——`通过（无命中）` 才能装。命中的话会列出**红线词与源脚本的行号**。

### 2.4 参数

| 参数 | 作用 | 缺省 |
|---|---|---|
| `--id <id>` | 包 id，`^[a-z0-9-]{2,32}$`，只能用小写字母 / 数字 / 连字符 | 由脚本 `@name` 推导 |
| `--name <名字>` | 列表里显示的名 | 脚本 `@name` |
| `--version-code <n>` | 版本递增整数。**同一个 id 再次安装时，必须比已装的大**，否则不覆盖 | `1` |
| `--version-name <串>` | 人读版本串 | 脚本 `@version` |
| `--line-name <名字>` | 命中线路展示名（播放在哪条源上取到的会显示它） | 同显示名 |
| `--out <路径>` | 输出文件；**不带扩展名时当成目录** | `./<id>.js` |
| `--force` | 预检命中时仍然产出 | — |
| `--no-lint` | 跳过预检（不建议） | — |
| `--quiet` | 只输出结果行 | — |
| `-h` / `--help` | 看帮助 | — |

退出码：`0` 成功；`1` 参数 / 读取 / 预检失败；`2` 生成失败。

::: warning 关于 `--force`
`--force` 只是让你拿到产物去看真实报错，**客户端依然会拒绝安装**。
预检规则与宿主侧的扫描是同一套，绕不过去。真要装，得改脚本里那行代码。
:::

### 2.5 想改一个源再重装

`--version-code` 加 1 即可，客户端按「同 id + 更大的 versionCode」认定这是更新：

```bash
node scripts/build-lx-pack.mjs "我的洛雪源.js" --id my-lx-source --version-code 2
```

## 3. 安装

产物是一个普通的播放包，走**本地文件**这条安装路径。

### 桌面端（Windows）

1. 打开 **设置 → 音源包**，滑到最底部
2. 在「安装音源包」区域点 **「从本地文件」**
3. 选中刚才生成的 `my-lx-source.js`
4. 确认弹窗会列出**类型 / 名称 / 版本 / 包 id / 来源**，核对后点「安装」
5. 装完**自动冒烟自检**，通过即生效

示意图见 [如何设置音源 · 桌面端](/source-setup#四、桌面端图文教程-从链接安装)（那条走的是链接，
本地文件在同一区域的另一个按钮）。

### 手机端（Android）

1. 首页「去安装」或 **设置 → 音源包管理**，滑到最底部
2. 「安装音源包」→ **从本地文件**
3. 选中文件（微信 / QQ / 网盘下载的都行），确认安装

::: tip 多包并存，试错很便宜
可以同时装多份播放包，**同一时刻只有一个生效**。列表里点「启用」即热切换，
会重新做一次冒烟自检。装坏了切回官方包就行。
:::

## 4. 验证

随便播一首歌。

- **出声 = 整条链路通了。**
- 不出声时，**弹出来的报错文字就是诊断信息**，照 [报错对照表](#_6-报错对照表) 定位。

播放器上还能看到这条歌是**哪条线路**取到的（显示的就是你 `--line-name` 给的名字），
用它确认歌确实走了你的洛雪源，而不是兜底到了别处。

## 5. 支持范围与已知边界

### 5.1 平台代号是翻译过的

洛雪脚本内部普遍这样分派平台：

```js
const apis = { wy: {...}, tx: {...}, kw: {...} };
lx.on("request", ({ source }) => apis[source].musicUrl(...));
```

轻听这边管网易云叫 `wyy`、QQ 音乐叫 `qq`，跟洛雪的 `wy` / `tx` 对不上。
打包器内置了对照表，**你不用关心，但排查时要知道**：

| 轻听 | 洛雪脚本里 |
|---|---|
| `wyy`（网易云） | `wy` |
| `qq`（QQ 音乐） | `tx` |
| `kw`、`kg`、`mg` 等 | 同名，恒等 |

### 5.2 大多数源能直接用，少数跑不通

我们对 40 多份真实洛雪源做过全量回归：**打包 100% 成功，绝大多数能正常取链。**
剩下的失败分两类：

- **源自身缺陷**：它声明支持某个平台，但内部的分派表和声明不一致（问到就炸）。
  这类报错会原样透出，改脚本才行。
- **能力边界**（下表），属于本方案的已知取舍。

| 能力 | 状态 |
|---|---|
| v2 源（`lx.on("request", …)`） | ✅ |
| v1 老脚本（`onRequest` / `module.exports.onRequest`） | ✅ |
| 平台代号翻译（`wyy→wy`、`qq→tx`） | ✅ |
| 源没声明这个平台 | ✅ 回人话「不支持该平台（它只声明了 …）」，不给英文报错 |
| `lx.utils.crypto`（md5 / AES / randomBytes） | ✅ |
| `lx.utils.buffer` / `base64` / `parseQuery` / `parseCookie` | ✅ |
| `lx.utils.zlib`（inflate / deflate） | ❌ 未实现，调用即抛 |
| `lx.utils.crypto.rsaEncrypt` | ⚠️ 恒返回空串（只在「配置上报」类路径用到，不在取链主链） |
| 需要用户在洛雪里填配置才能用的源 | ⚠️ 不经洛雪 UI 配置，依赖配置项的取链会失败 |
| 依赖 `GM_*`、`unsafeWindow` 等油猴环境的脚本 | ⚠️ 不在 `lx` 协议面内，不保证可用 |
| 搜索 / 歌词 / 封面 | ❌ 数据包职责，播放包不做 |

### 5.3 脚本仍然跑在沙箱里

兼容不等于放权。脚本运行时能用的**只有宿主注入的 `request` 通道**——
`fetch` / `XMLHttpRequest` / `WebSocket` / `Worker` / 文件系统全部不可用，
也够不到宿主与系统的任何原生桥。

有些源脚本会直接写裸 `fetch(url)`。这类脚本**打包时就会被预检拦下**并报出行号，
因为它绕过宿主出口、在客户端里根本发不出去。

## 6. 报错对照表

| 看到的现象 | 意思 | 怎么办 |
|---|---|---|
| 打包时报「预检命中」+ 红线词 + 行号 | 脚本里有绕过宿主的网络 / 宿主桥调用 | 按行号改脚本；`--force` 只能帮你看到错，装不上 |
| 客户端报「命中内容安全红线」 | 同上，宿主侧扫到了 | 同上 |
| `洛雪源「X」不支持该平台（它只声明了 wy/tx/kw）` | 这个源自己没申报你要播的平台 | 换首歌或换个平台；不是你的错 |
| `洛雪源「X」取链失败（wyy/320）：…` | 源内部真的取不到 | 后半段是源自己的话，多半是版权或接口维护 |
| `Cannot read properties of undefined` | 源自身的缺陷（分派表与声明不一致） | 换源；改脚本也行 |
| 装完标着「上次失败」 | 冒烟自检没过 | 多数是当时网络不通，重试一次 |
| 提示签名校验失败 | 用了官方保留 id（`play-official` 等） | 换一个自己的 id |
| 能播但搜不到东西 | 洛雪包只管取链 | 去装[官方数据包](/source-setup#二、官方音源直链-可直接复制) |

更多见 [问题答疑](/faq)。

## 7. 想自己改 / 当库用

打包器除了命令行，也导出一个函数，适合嵌进你自己的工具链：

```js
import { buildLxPlayPack, toPackId } from "qt-sources-sdk/src/build-lx-pack.js";
import { writeFileSync, readFileSync } from "node:fs";

const result = buildLxPlayPack({
  scriptText: readFileSync("我的洛雪源.js", "utf8"),
  id: "my-lx-source",
  versionCode: 1,
});
if (!result.ok) {
  console.error(result.error);   // 一句人话
  process.exit(1);
}
writeFileSync(result.fileName, result.text);
```

`src/lx-runtime.js` 里的 `createLxBridgeRuntime` 也单独导出——想自定义装配
（自己写工厂、自己管调用时机）可以直接用。

打包器自带一套自测，改完跑一遍：

```bash
node scripts/test-lx-packer.mjs     # 或 pnpm test:lx
```
