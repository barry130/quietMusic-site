# 问题答疑

::: tip 先看这里
90% 的问题答案是同一句：**在线能力来自第三方公开接口，不是官方授权，随时可能变。**

遇到失败先按这个顺序试一遍，大多数情况当场就好：

1. **换一首歌** —— 判断是单曲问题还是整个源的问题
2. **换一个音源** —— 播放页可以直接切源
3. **去设置页检查音源包更新** —— 接口改了，推个新包就能修
4. **确认装过播放包** —— 从未装过的话，在线播放本来就不存在
:::

## 安装与音源包

### 「未安装播放音源包」是什么意思？

轻听把在线取链逻辑放在**音源包**里，应用本身不内置任何第三方取链实现。
首页的提示是引导你去音源包管理页安装。

**其余功能完全不受影响** —— 播放、歌词、下载、收藏、统计照常工作。

完整的安装步骤见[如何设置音源](/source-setup)。

### 音源包和 App 更新有什么区别？

| | 音源包更新 | App 更新 |
|---|---|---|
| 改了什么 | 第三方接口、取链线路、音源清单 | 客户端功能、界面、原生能力 |
| 怎么装 | 设置页「检查更新」 | 应用内弹窗 / 下载安装包 |
| 要不要重装 App | 不需要 | 需要 |
| 检查频率 | 启动预热 + 4 小时节流 | 随启动检查 |

接口失效这类问题，推一个音源包就能修，不用等新版客户端——这是这套设计的主要目的。

### 音源包有哪几种？

| 包 | id | 作用 |
|---|---|---|
| 官方数据包 | `meta-official` | 搜索 / 歌单 / 歌词 / 封面等**元数据**入口 |
| 官方播放包 | `play-official` | 在线**取链**（把一首歌解析成播放地址） |
| 第三方包 | 自定义 | 自己写的包，用自己的 id |

数据面与取链面分开，意味着**取链实现（风险较高的那一半）可以独立更换**，而搜索、
歌单这些体验不受牵连。这也是 `play-official` 由用户自行安装、官方仓库不内置的原因。

### 可以装多个音源包吗？

可以，多包并存，同一时刻只有一个生效。列表里能看到每包的来源（链接 / 本地 /
官方）与最近失败原因，切换会即时热装载并做取链冒烟自检——试错成本很低。

### 装不上 / 提示签名校验失败？

`play-official` 与 `meta-official` 是官方保留 id，**只有带官方 ed25519 签名的包
才能用**。没私钥的自称官方包会被直接拒绝（不是警告，是装不上）。
第三方包请用自己的 id（`^[a-z0-9-]{2,32}$`）。

### 装不上 / 提示命中内容安全红线？

安装时客户端会扫包文本，命中下列任一特征直接拒绝，**错误信息会给出命中词与行号**：

- 宿主桥：`__TAURI_INTERNALS__`、`__TAURI__`、`ipcRenderer`、`webkit.messageHandlers`、`UTSAndroid`、`io.dcloud`
- 自由外联：`WebSocket`、`EventSource`、`sendBeacon`、`new XMLHttpRequest`、裸 `fetch(`、`require(`
- 后台执行体：`importScripts`、`new Worker(`、`ServiceWorker`、`serviceWorker`
- 本地 / Node 面：`child_process`、`process.binding`、`content://`

::: details `fetch(` / `require(` 的误伤规避
这两个按**调用形态**识别：前一字符是字母 / 数字 / `_` / `$` / `.` 的不算。
所以 `backend.fetch(id)`、`prefetch(url)`、`myrequire(x)` 不误伤，
裸 `fetch(url)`、`await fetch(url)` 才拦。
:::

::: details 为什么 `eval(` / `Function(` 不在拦截列表里？
不是漏了，是**刻意不拦**。crypto-js 这类主流第三方库开头就有
`Function("return this")()` 的环境探测，拦了会大面积误杀正常包。
而且引擎里网络出口、文件系统、宿主桥都已封死，动态执行拿不到额外能力。
:::

### 官方包也会被拦吗？

不会。已验签的官方保留 id 命中规则时**只记日志、不阻断**——签名本身就是更强的一致性保证。

## 播放与音质

### 为什么播放的不是原曲？

本应用通过换源机制从各平台公开接口取播放地址，数据并非官方授权、也不保证准确，
可能出现翻唱、Live、串曲或不同平台版本。**属正常现象**。

### 为什么搜到的歌点不开，或突然就失败了？

接口随时可能被上游调整或限制。按开头那四步排查即可；如果是**从没装过播放包**，
在线播放本来就不会工作，不是故障。

### 为什么显示无损却只有几 MB？

音质取决于上游线路，部分线路实际音质与标称不符。客户端已经做了两件事尽量贴近现实：

- **优先选可用的高音质来源**；
- **按实测码率重标档位**（只降不升）。所以请求无损实际拿到 320k 时，
  下载文件不会虚标成 `.flac`。

另外，声明里没有的音质档位**不会在界面上展示**——比如 B 站音频流没有真无损
（flac 档实际是最高档 AAC），就不会给你 flac 选项。

### 三档音质分别是什么？

| 档位 | id | 说明 |
|---|---|---|
| 标准 128k | `128` | 体积最小，流量友好 |
| 高品 320k | `320` | 日常推荐 |
| 无损 FLAC | `flac` | 看源支持情况，不保证每首都拿得到 |

**播放音质与下载音质相互独立**，可以「在线听着 320k、下载存无损」。

### 播放会卡顿或中断？

音源线路稳定性不一，个别歌曲的可用线路较少。失败时应用会自动尝试其它来源或跳到
下一首。

### 播放失败为什么会自动跳下一首？

这是有意设计：避免卡在坏地址上。连续失败多首后会自动停下并提示，不会无限跳。

### 歌曲必须联网吗？

在线播放需联网。已播过的歌会**边播边缓存**（Android，上限可调），重复播放不走网络；
下载到本地的歌可离线播放。

## 歌词与封面

### 为什么封面 / 歌词偶尔缺失或对不上？

封面与歌词同样来自各平台公开接口，可能出现缺失、错位或有延迟。

### 有逐字歌词吗？

看音源包。契约里支持**逐字歌词**（QRC 行内格式）与**罗马音 / 注音**两种可选面，
取不到就是空串，此时正常显示普通 LRC，不影响播放。

::: tip 桌面歌词也认逐字
Android 的桌面歌词窗口有逐字就按逐字行渲染，没有就解析普通 LRC（与播放页同口径）。
译文会按时间戳就近补挂。不过逐字行**不做逐词染色**——原生窗只有一个文本视图且按行推送。
:::

## 桌面歌词（Android）

### 开了没反应？

需先授予「悬浮窗 / 显示在其他应用上层」权限。客户端的授权页按
**厂商私有权限页 → AOSP 页 → 应用详情页**逐级降级，所以不同机型跳到的地方不一样
（vivo / iQOO 的开关在 i管家 → 权限管理 → 悬浮窗）。从设置页返回后，已授权则会自动开启。

### 为什么每次启动都是关闭的？

该开关是**运行期状态**，每次启动默认关闭，需要时手动开启。这是刻意设计——
避免一个常驻悬浮窗在你不知情的情况下一直挂着。

### 锁定了有什么用？

锁定后点击穿透，不影响你操作下面的应用，歌词照常滚动。

### 歌词样式能改吗？

能。字号、颜色、字体都可以调，**改完即时生效**，不用重启。

## 本地音乐

### 支持哪些格式？

MP3 / FLAC / WAV / OGG / AAC / M4A。**两端一致**。

APE / WMA / DSD 暂不支持（两端解码链路同理未接）。

### 为什么删不掉本地文件？

删除**第三方公共媒体**文件受 Android 分区存储限制，需要「所有文件访问」
（`MANAGE_EXTERNAL_STORAGE`）权限。未授权时界面会引导去系统设置开启，开启后即可删除。
**应用自有的文件不受此限制。**

本地音乐右上角 ⋮ →「删除设置」可选：

- 「仅从列表移除，保留文件」（**默认**）
- 「删除时同时删除本地文件」

### 扫描会不会把整张卡都扫一遍？

可以指定文件夹，也可以设**最小文件大小过滤**，避免把提示音、缓存碎片一起收进库。
Windows 端是目录级管理。

### 本地播放需要账号吗？

不需要。账号只影响云同步（收藏、歌单）与签到一类的在线功能。

## 账号与同步

### 换手机后收藏还在吗？

登录同一账号会自动同步。断网时的收藏会**暂存本地**，联网后自动补推；
每次启动还会与服务器做存在性对账，服务器缺失的收藏自动补推恢复。

### 支持哪些登录方式？

**登录**用邮箱或用户名；**注册**需要用户名 + 邮箱。用户名长度 3–30 个字符。

忘记密码走邮箱验证码找回。

### 上传头像为什么一直失败？

头像上传有明确的额度和格式限制：

| 限制 | 值 |
|---|---|
| 单文件大小 | ≤ 2 MB |
| 格式 | PNG / JPEG / WebP |
| 次数 | 每人每天 2 次 |

失败请间隔一段时间重试。头像只在**修改时**才会上传，日常使用不消耗额度。

## 设置项速查

不同平台的设置项略有差异，Android 端比较完整：

| 设置项 | 可选值 / 说明 |
|---|---|
| 默认音源 | 由音源包声明的源清单，未装包时提示先安装 |
| 播放音质 / 下载音质 | 标准 128k / 高品 320k / 无损 FLAC（按当前源收敛） |
| 默认倍速 | 播放页与下载共用 |
| 定时关闭 | 关闭 / 10 / 30 / 60 分钟后 / 播放完当前歌曲后 |
| 同时播放 | 不允许（独占音频）/ 部分场景（压低音量）/ 全部场景 |
| 同时下载数 | 过高会提示「并发偏高」 |
| 下载文件名格式 | 「歌手 - 歌名」/「歌名 - 歌手」 |
| 音乐缓存上限 | 默认 1024 MB，预设 512 MB ~ 16 GB，也可自定义；原生层最小 256 MB |
| 均衡器 | 五段：60Hz / 230Hz / 910Hz / 3.6kHz / 14kHz |
| 外观与皮肤 | 明暗模式 + Linen / Graphite / Aurora 预置皮肤 |
| 不喜欢列表 | 被标记的歌曲不再参与推荐 |

### 均衡器有哪些预设？

平直 / 流行 / 摇滚 / 古典 / 爵士 / 电子 / 低音增强 / 人声，共 8 种；
也可以直接拖五段滑块，滑块值会实时换算成 dB 显示。

**均衡器关闭时改曲线只保存不生效**，下次开启自动套用；开着改则即时生效。

### 三套皮肤分别是什么风格？

| 皮肤 | 风格 |
|---|---|
| Linen | 暖白纸张与珊瑚红 |
| Graphite | 中性石墨与清晰层次 |
| Aurora | 蓝紫层次与通透玻璃 |

每套都有亮色与暗色两版，跟随系统或手动指定。还可以自定义背景与配色。

## 其他

### 提示更新要不要装？

建议装。新版本会修复失效的接口与已知问题。音源包更新同理，且不要求重装 App。

### 为什么没有批量下载 / 批量收藏？

批量操作对服务器压力很大，服务端是个人搭建的，承受不了，暂无计划支持。

### 支持 iOS 吗？

代码层面是一套（UniAppX 可编译 iOS），但目前**没有正式发布 iOS 版本**。

### 支持鸿蒙吗？

暂未单独适配。

### 我该怎么反馈问题？

应用内「意见反馈」，或者在 [反馈与贡献](/feedback) 页列出的 GitHub / CNB 渠道提交。
提交反馈时**设备型号、系统版本、应用版本号**会一并上传，便于定位——
这是唯一会上送的设备信息，详见[隐私政策](/privacy)。

## 还没解决？

请提交时尽量带上：

- **应用版本**（关于页可看）与**音源包版本**（设置页音源包管理）
- **具体歌曲名 + 音源**（例如「《xx》 / 网易云」）
- **失败提示的原文**（照抄即可，错误信息里常带关键线索）
- 是偶发还是必现；换源 / 换歌后是否还复现
- 涉及本地文件时，说明文件格式与来源

信息越全越容易定位。
