# 问题答疑

::: tip 先看这里
90% 的问题答案是同一句：**在线能力来自第三方公开接口，不是官方授权，随时可能变。**
遇到失败先换一首 / 换音源 / 去设置页检查音源包更新。
:::

## 安装与音源包

### 为什么首页提示「未安装播放音源包」？

轻听把在线取链逻辑放在**音源包**里，应用本身不内置。首页的提示是引导你去
「设置 → 音源包管理」安装。**本地音乐播放完全不受影响**。

### 音源包和 App 更新有什么区别？

| | 音源包更新 | App 更新 |
|---|---|---|
| 改了什么 | 第三方接口、取链线路 | 客户端功能、界面、原生能力 |
| 怎么装 | 设置页「检查更新」 | 应用内弹窗 / 下载安装包 |
| 要不要重装 App | 不需要 | 需要 |

接口失效这类问题，推一个音源包就能修，这是这套设计的主要目的。

### 可以装多个音源包吗？

可以，多包并存，同一时刻只有一个生效。列表里能看到每包的来源（链接 / 本地 /
官方）与最近失败原因，切换即时热装载并做取链冒烟自检。

### 装不上 / 提示签名校验失败？

`play-official` 与 `meta-official` 是官方保留 id，**只有带官方 ed25519 签名的包
才能用**。没私钥的自称官方包会被直接拒绝（不是警告，是装不上）。
第三方包请用自己的 id。

### 装不上 / 提示命中内容安全红线？

安装时客户端会扫包文本，命中下列任一特征直接拒绝（错误信息会给出命中词与行号）：

- 宿主桥：`__TAURI_INTERNALS__`、`ipcRenderer`、`UTSAndroid`、`io.dcloud` 等
- 自由外联：`WebSocket`、`EventSource`、`new XMLHttpRequest`、裸 `fetch(`、`require(`
- 后台执行体：`importScripts`、`new Worker(`、`ServiceWorker`
- 本地 / Node 面：`child_process`、`process.binding`、`content://`

::: details `fetch(` / `require(` 的误伤规避
这两个按**调用形态**识别：前一字符是字母 / 数字 / `_` / `$` / `.` 的不算。
所以 `backend.fetch(id)`、`prefetch(url)`、`myrequire(x)` 不误伤，
裸 `fetch(url)`、`await fetch(url)` 才拦。
:::

## 播放与音质

### 为什么播放的不是原曲？

本应用通过换源机制从各平台公开接口取播放地址，数据并非官方授权、也不保证准确，
可能出现翻唱、Live、串曲或不同平台版本。**属正常现象**。

### 为什么搜到的歌点不开，或突然就失败了？

接口随时可能被上游调整或限制。建议按顺序排查：

1. 换一首试试（单曲问题还是整源问题）
2. 切换音源（播放页可切源）
3. 去设置页「音源包」检查更新
4. 若从未装过音源包，先装

### 为什么显示无损却只有几 MB？

音质取决于上游线路，部分线路实际音质与标称不符。客户端已尽量优先选择可用的高
音质来源，但无法百分百保证。另外，声明里没有的音质档位**不会在界面上展示**——
比如 B 站音频流没有真无损（flac 档实际是最高档 AAC），就不会给你 flac 选项。

### 播放会卡顿或中断？

音源线路稳定性不一，个别歌曲的可用线路较少。失败时应用会自动尝试其它来源或跳到
下一首；播放失败会自动切歌，连续多次失败则停下并提示。

### 播放失败为什么会自动跳下一首？

这是有意设计：避免卡在坏地址上。连续失败多首后会自动停下并提示，不会无限跳。

### 歌曲必须联网吗？

在线播放需联网。已播过的歌会**边播边缓存**（Android，上限可调），重复播放不走网络；
下载到本地的歌可离线播放。

## 歌词与封面

### 为什么封面 / 歌词偶尔缺失或对不上？

封面与歌词同样来自各平台公开接口，可能出现缺失、错位或有延迟。

### 有逐字歌词吗？

看音源包。契约里支持**逐字歌词**（QRC 行内格式）与**罗马音 / 注音**两种可选面，
取不到就是空串，此时正常显示普通 LRC，不影响播放。

## 桌面歌词

### 开了没反应？

需先授予「悬浮窗 / 显示在其他应用上层」权限。客户端的授权页按
**厂商私有权限页 → AOSP 页 → 应用详情页**逐级降级（vivo / iQOO 的开关在
i管家 → 权限管理 → 悬浮窗），从设置页返回后已授权则自动开启。

### 为什么每次启动都是关闭的？

该开关是**运行期状态**，每次启动默认关闭，需要时手动开启。这是刻意设计——
避免一个常驻悬浮窗在你不知情的情况下一直挂着。

### 锁定了有什么用？

锁定后点击穿透，不影响你操作下面的应用，歌词照常滚动。

## 本地音乐

### 为什么删不掉本地文件？

删除**第三方公共媒体**文件受 Android 分区存储限制，需要「所有文件访问」
（`MANAGE_EXTERNAL_STORAGE`）权限。未授权时界面会引导去系统设置开启，
开启后即可删除。应用自有的文件不受此限制。

本地音乐右上角 ⋮ →「删除设置」可选「仅从列表移除，保留文件」或
「删除时同时删除本地文件」，默认仅移除。

## 账号与同步

### 换手机后收藏还在吗？

登录同一账号会自动同步。断网时的收藏会**暂存本地**，联网后自动补推；
每次启动还会与服务器做存在性对账，服务器缺失的收藏自动补推恢复。

### 上传头像为什么一直失败？

头像上传走第三方接口，有稳定性和额度限制，失败请间隔一段时间重试。
每人每天最多上传 2 次。

## 其他

### 提示更新要不要装？

建议装。新版本会修复失效的接口与已知问题。音源包更新同理，且不要求重装 App。

### 为什么没有批量下载 / 批量收藏？

批量操作对服务器压力很大，服务端是个人搭建的，承受不了，暂无计划支持。

### 支持 iOS 吗？

代码层面是一套（UniAppX 可编译 iOS），但目前**没有正式发布 iOS 版本**。

### 支持鸿蒙吗？

暂未单独适配。

### 我该怎么反馈问题？

应用内「意见反馈」，或 [GitHub Issues](https://github.com/barry130)。
提交反馈时**设备型号、系统版本、应用版本号**会一并上传，便于定位——
这是唯一会上送的设备信息，详见[隐私政策](/privacy)。

## 还没解决？

请提交时尽量带上：

- 应用版本（关于页可看）与音源包版本（设置页音源包管理）
- 具体歌曲名 + 音源
- 失败提示的原文

信息越全越容易定位。
